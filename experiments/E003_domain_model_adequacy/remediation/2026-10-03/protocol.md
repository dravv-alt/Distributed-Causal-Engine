# E003-AM001 remediation protocol — frozen before implementation

Question: can explicit file time evidence, conservative resource typing, deployment relations, unresolved trace states, metric semantics and separate evaluation storage repair E003's representation problems without inventing facts?

Hypothesis: the engineering defects are repairable, but absent source semantics and incomplete coverage may still block adequacy. Reference: exact source CSV records, file headers/date scopes, label epoch/datetime agreement, deployment workbook cells and independently specified adversarial fixtures. No RCA accuracy is measured.

Independent variables: all four scenarios, every telemetry file/schema/modality. Controls: immutable raw ZIPs, v1 unchanged, exact source strings retained, deterministic file/row selection, no randomized selection, no unit inference from metric names, labels accessible only to evaluator. Seeds: null.

Coverage design: census of headers and ZIP sizes; full label/query census; deterministic first 512 telemetry rows per file across every available date. Prefixes establish schema and implementation behavior, not incident or population completeness. This is an operational screening strategy, not a statistically representative sample. No claim of whole-file timestamp uniformity. A disk-backed streaming path supports a separately recorded full scan; V001 deliberately screens before authorizing 64 GiB processing. Traces are resolved only within this bounded context; unresolved parents remain explicit. Any file requiring assumptions is quarantined and blocks its semantic gate.

Timestamp candidates s/ms/us/ns must be validated against source-local UTC+08 date and a fixed one-hour boundary allowance, never magnitude alone. File interpretation requires a unique candidate supported by >=99% of sampled values in the extended window and no rows supporting another scale. Boundary allowance aids profiling only: mapping uses strict source-day bounds. Mixed scales are ambiguous, invalid values are rejected, and out-of-day rows remain quarantined. Labels validate UTC+08 via datetime agreement; they never choose telemetry units.

Metrics retain source strings and explicit UNKNOWN units/kind/temporality/aggregation unless a reviewed source-backed registry entry exists. Trace durations and status tokens stay raw/UNKNOWN; no end times are synthesized. Workbook Type/Host/Name cells support identities and RUNS_ON only when explicit; merged cells resolve only within declared merge ranges. Container alias cells are candidates pending review and do not merge IDs. dsName stays an unverified resource hint.

Conservation: scanned = mapped + rejected + ambiguous + out_of_window + unsupported. Every disposition has a source pointer and raw fields in disk-backed provenance. Exact duplicate rows are counted with a disk index and preserved as individual records. Missingness and identity/trace counts cover scanned rows only. Canonical replay sorts by event time, opaque source key, logical row and ID; two complete passes must have identical canonical digests. Performance measures include elapsed wall time, throughput, process peak working set when available, output size and coverage limitations.

Gates A–H are the attached prompt's gates. PASS requires direct evidence for every condition; incomplete source semantics/coverage/leakage checks are PARTIAL, never PASS. All gates must PASS to unlock RCAEval. A critical ambiguity/unsupported schema stops downstream work after its evidence/report is retained. No threshold, seed, subset or gate changes after results. Decision outcomes per current prompt: ACCEPT/REVISE/REJECT/BLOCKED; human review stays pending.
