# Checklist for each authorized task

## Recover and authorize

- Read AGENTS → constitution → checkpoint/machine state → live register → active experiment evidence → roadmap/stage → scientific contracts.
- Verify exact checkout, dirty state and scope. Resolve conflicts explicitly; no neighboring checkout or self-approved gate.
- Name the RQ, planning key and allocated permanent E-ID. Confirm predecessor outcomes and actual human authorization, including any permission to alter existing files.
- If blocked, stop advancement and report the gate. Read-only review and requested new governance files are not downstream execution.

## Design before substantial code

- Define question/hypothesis, independent/dependent variables, controls, independent baseline/reference and source-record reconstruction expectations.
- Freeze selection/splits, label isolation, seeds/configuration, metrics, acceptance thresholds/uncertainty and failure conditions. Missing thresholds remain unapproved, not guessed.
- Identify dataset manifest, code commit/dirty/source hashes/snapshot, dependency versions and hardware/workload.
- Define deterministic run ID, non-overwriting outputs, safe data handling, allowed actions and exclusions. Use approved experiment registration; roadmap IDs do not allocate E-numbers.

## Implement and execute the instrument

- Implement only the experiment's missing capability, using explicit domain contracts and tests.
- Preserve raw/source semantics and UNKNOWNs; fixtures include malformed, missing, duplicate, ordering, topology and label-leakage cases as relevant.
- Execute the resolved configuration; preserve successful/failed attempts separately. Never change controls mid-run and present old results as the changed experiment.
- Record exact commands, limits, time, seed rationale, environment, hashes and artifacts. Static tests are not deployed behavior or scientific quality.

## Analyze and review

- Check conservation, reproducibility, coverage, baseline independence, leakage and uncertainty.
- Separate observed outcomes from interpretation. Categorize model, engineering, source, coverage and environment failures. Report negative/inconclusive results.
- Produce report, figures/tables where useful, failure analysis and evidence-backed decision proposal (PROCEED/REVISE/REPEAT/BRANCH/ABANDON).
- Obtain reviewer, date and explicit next permitted scope. Pending recommendation is not approval.
- Preserve existing records. Add new dated amendments/checkpoints only within authority; do not overwrite executed results, frozen protocols or registry identities.

## Recoverability handoff

- Provide artifact paths, verified/unverified boundaries, actual gate status and next permitted action.
- New checkpoint includes current ID/run, result/source hashes, defects, pending approvals, next allowed work and commands that are references rather than launch permissions.
- Do not advance just because the next card exists.
